# fueledbychai-rs

Venue-agnostic trading connectivity for Rust: market data and order entry behind common traits,
with one crate per venue. The Rust counterpart of
[FueledByChaiTrading](https://github.com/FueledByChai/FueledByChaiTrading).

First venues: Paradex, then Hibachi; Binance USD-M futures for reference market data.

Status: scaffolding. The Cargo workspace exists with five crates:

| Crate | Status |
| --- | --- |
| `fbc-core` | Time kinds, units, exact prices (`PxExact`), money and price grids (fixed, significant-figure, banded); sealed order and fill ids, the canonical client-id codec, restart-safe minting under a namespace lease, `Fee` (positive means we paid) and the per-account `FeeBook`, `DecodeScope`, `InstrumentSpec` with maker-safe quantization, `VenueCaps` with every field mandatory (order and fill capabilities together in one optional `exec` block, `None` for market data only; decision 0015), and the venue boundary: market-data and execution events, venue commands and their outcomes, and the sans-IO `MdCodec`, `ExecCodec`, `OrderSigner`, `NonceSource` and `VenueFactory` traits with `Effects` and `EncodeCtx` |
| `fbc-book` | A tick-indexed L2 book per instrument and book channel, built from normalized book events the same live and in replay: snapshots replace it, deltas set and remove levels, a window bounds it, a gap invalidates it until the next complete snapshot; touch, top-n, an exact top-n comparison naming the first differing level, and canonical bytes |
| `fbc-journal` | The journal's record format (inbound frames with their stamps, outbound frames and write results, HTTP requests and results with headers, timers, control records and markers), a writer of one subdirectory per UTC day with `<shard>-<seq>` segments, and a reader in write order; redaction spans and secret headers are never written; a sink that never blocks, with a soft limit for normal records, a safety reserve, drops counted by class and a `Degraded` marker, drained by a writer thread (decisions 0006, 0021) |
| `fbc-runtime` | The one connector every connection goes through (`ProxyConfig::Direct` or `ProxyConfig::Socks5 { host, port }`, a hand-written no-authentication SOCKS5 CONNECT that names the target by host name so the proxy resolves it), with a WebSocket client (`ws://`, `wss://`) and an HTTP/1.1 call (`http://`, `https://`) over it; TLS runs on the connector's stream with rustls and the ring provider, trusting webpki-roots plus anchors the consumer adds (decisions 0019, 0020); errors name the failed step and never the URL. Connection epochs that drop and count a dead connection's late frames, timers, HTTP results and events, and a subscription reconciler that sends only the difference and each epoch's set once, as logic without a socket. A market-data session (`MdSession`) that drives one socket endpoint over them: a fresh codec per epoch, events stamped and handed to the consumer's `MdHandler` in ingest order, the codec's frames, timers and reconnects executed, and reconnects paced by the consumer's backoff and attempt budget (decision 0023) |
| `fbc-venue-paradex` | The Paradex signer (`src/sign`, owner-reviewed): the SNIP-12 revision 0 typed-data hash of `Order`, `ModifyOrder` and the auth `Request` and its Stark-curve ECDSA signature with RFC 6979 nonces, behind `OrderSigner`, held to the Java library's vectors in `fixtures/paradex/signing/`. Market data (`src/md`): an SBE reader gated on each frame's stated block lengths, `bbo` and `trades` decoded into touches and trades, the `order_book` deltas channels into book events with every seq_no discontinuity reported and resynced by reconnect (0022), and a `VenueFactory` declaring market data only (`exec: None`), held to hand-built frames in `fixtures/paradex/md/` |

No venue is supported yet: Paradex has its signer and its bbo, trades and order book market data, not yet order entry.
